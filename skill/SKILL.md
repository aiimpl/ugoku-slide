# 動くスライド（ugoku-slide）

62 種類の雛形（`templates/`）から1つを選び、中身を差し替えて、1ファイルの HTML スライドを仕上げる。
仕組み（ページ送り・計算・変形・印刷）は各ファイルに入っているので、書き換えるのは中身とデザインの `<style>` だけ。

## 手順

1. **場面を決める**：誰に・どんな場で・何を決めてもらうか。ユーザーの話から読み取れなければ、1回だけまとめて聞く。
2. **雛形を選ぶ**：`templates/index.json` を読み、`aim`（誰が・どんな場面で）と `use` と `features` が近いものを選ぶ。
   迷ったら2〜3本を名前と理由つきで示して選んでもらう。ユーザーが様式を指定していればそれを優先。
   - ページをめくっても図形がつながってほしい → `features` に `morph`（51・52・55・56・57・58・60・61・62）
   - 回して見せたい製品・構成 → `orbit`（53・56・61）
   - 毎月の数字を貼り替えたい → `sheet`（54・62）
3. **写して書き換える**：選んだファイルを作業フォルダにコピーし、本文の `<main class="deck" …>` の中の `<section class="slide">` を書き換える（先頭のコメントの中にも同じ文字があるので、文字で探すときは `</style>` より後ろを探す）。
   **先に `reference/rules.md` を全部読む**（書き換える場所・消し忘れやすい所・座標で置いたページの直し方が書いてある）。
   - 「ugoku-slide engine」の BEGIN〜END は変えない。
   - 色と書体は 2つ目の `<style>` の `:root`。図形の位置や大きさが CSS の座標で決まっているページは、その CSS も数字に合わせて直す。
   - 使える部品は `reference/parts.md`。部品の一覧に無い class は、その雛形の中の使い方をまねる。
   - 1枚ごとの動かし方は、言いたいことの形で決める（`reference/rules.md` の「1枚ごとの動かし方」）。1ページに操作は1つ。
4. **確かめる**：下の「仕上げの確認」を全部通す。
5. **別の目で見る**：`reference/review.md` のとおり、作り方を知らないサブエージェントに画像だけを見せ、指摘を採否表にして直す。
6. **渡す**：HTML ファイル1つとして渡し、次を一言添える。
   「ダブルクリックでブラウザで開く・→ で送る・F で全画面・D で自動デモ・E で直したい所を囲むと直しの指示が作れる・⌘P で PDF」
   仮の数字を置いたなら、どれが仮かを一覧で伝える。

## 中身の決まり（要点。全部は reference/rules.md）

- 利用者の話と数字を使う。雛形の架空の会社名・人名・数字は、`<title>` や CSS の中の値まで全部消す。
- 足りない数字を作ったら、作ったことを伝え、スライドにも「仮の数字」と書く。
- 1枚に言いたいことは1つ。見出しは結論の一文。スライダーで動く数字を見出しで言い切るなら、見出しも式で出す。
- 数字の話は `data-calc` で、見る人が動かして確かめられるようにする。根拠・出典・計算式は `<details class="why">` に入れる。
- 説明の文・箇条書き・表の中身は 18px 以上（注記・目盛り・根拠の中の文・ページ番号は雛形の大きさのまま）。
- 発表者メモ `<aside class="notes">` を各スライドに付ける。

## 変形（data-morph）を使うとき

雛形の `<main class="deck" data-transition="morph">` では、前後のページで同じ `data-morph="名前"` を持つ要素が変形してつながる。
中身を差し替えても、この「同じものが形を変えて続く」筋書きは残す。

- 同じ名前は、前後のページで同じもの（例：この事業・この工程・この人）を表すこと。
- 文字の入った箱は、背景だけの要素（雛形により `.plate`・`.pc` など名前はちがう）に `data-morph` を付け、文字には `data-morph-enter` を付ける。
- 名前が次のページに無ければ、変形せず普通に消える・現れる。詳しいコツは `reference/rules.md`。
- 位置は left/top・grid・flex で決める。transform で動かさない。

## 仕上げの確認

コードを実行できる環境なら、スキルの `scripts/check.py` で開いて確かめる（要 playwright。`pip install playwright`、Chrome が無ければ `playwright install chromium`）：

```
python3 <スキルのフォルダ>/scripts/check.py 出来上がり.html --morph --final
```

- エラー・枠からのはみ出し・動かない計算・根拠を開いたときや表を貼り替えたときのはみ出し・表の集計の計算できない式は「問題」として出る。直して「問題なし」になるまで繰り返す。
- 文字が背景に沈む（コントラスト不足）も「問題」。文字の色を濃く（明るく）する。
- 「要確認」は、画像を見て判断する。文字の重なり・下の空き・操作が多すぎる・ありがちな言い回し・見出しの数え上げの食い違いなど。
- 「情報」の「つながり 5/6」は、ページの境目のうち、変形でつながる所の数（data-morph の雛形のとき）。
- 画像は出来上がりと同じフォルダの `check/<名前>/` に出る。**「問題なし」でも必ず画像を見る**：
  `NN.png`（全部出した状態）で文字と図の重なり、`NN-0.png`（→ を押す前）で空きすぎ、`NN-why.png`（根拠を1つずつ開いた状態）で図が潰れていないか、
  `NN-sheet.png`（表を1.4倍・3行多くして貼った状態）でグラフと見出しが収まっているか、`NN-t100/250/450.png` で変形の途中の崩れ。
  check.py が見るのは文字だけなので、図形や箱が枠からはみ出していないかも画像で見る。

実行できない環境なら、少なくとも次を目で確かめる：
- 各スライドの文字量が雛形と同じくらいか、少ないか（増やしすぎると枠からはみ出す）
- `data-out` の式に出てくる名前が、すべて `<input name="…">` か `data-let` にあるか
- `data-morph` の名前の組が、前後のページでそろっているか
