5つの層は、決まった窓口（API）だけでつながる。1つの層を直す・増やすときに、ほかの層を止めなくていい。

今は5つの役割が1つのプログラムに入っている。どこを直しても、全体を試験して全体を止める。

受注の処理が落ちても、画面と API は注文の受付を続け、データは失われない。復旧したら、たまった注文を順に処理する。影響は「確定が最大15分遅れる」まで。

同じ障害で、画面からデータまで全部が止まる。昨年度はこれが9回・41時間あった。

ドラッグで回せます ／ ダブルクリックで元の向き
会場で「障害が起きたとき」を押す。赤く沈むのは業務ロジックの1層だけ。次に「今の構成で比べる」を入れると、板がくっついて一枚岩になり、全部が赤く沈む。この2つの見比べがこの提案の芯です。
